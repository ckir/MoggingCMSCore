# MoggingCMSCore Plan 3: `@mogging/ai` (jobs, providers, validation, budgets)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver `@mogging/ai`: the staleness-driven translation pipeline of spec section 8 (enqueue stale fields as jobs, claim them under a budget, translate with a model through the Vercel AI SDK, validate structurally and terminologically, record `DRAFT_AI` snapshots through `@mogging/core`), plus the `compile`, `jobs` and `provenance` SDK functions the CLI (plan 4) wraps.

**Architecture:** A new workspace package `packages/ai`. It owns every statement on `ai_jobs`, `ai_budgets` and `glossary`, writes the discarded-cost rows of `content_provenance`, and performs every content write through core's `recordAiDraft` inside its own job transaction (postgres.js nests `sql.begin` as a savepoint, measured in plan 2). Rich text travels as one sentinelized Markdown string per field inside a structured JSON object (`sentinelize` / `restoreDraft` from `@mogging/markdown`), as the spike decided. The model is an AI SDK `LanguageModel`: OpenRouter is built in; any other model is passed in by the adopter.

**Tech Stack:** TypeScript 5, Node >=22, pnpm workspace, vitest 5, `@mogging/core` and `@mogging/markdown` (workspace), `postgres@^4`, and pinned exactly as the spike measured them: `ai@7.0.154`, `@openrouter/ai-sdk-provider@3.1.0`, `zod@4.6.7`. Tests use `MockLanguageModelV3` from `ai/test`.

**Spec:** `docs/superpowers/specs/2026-11-11-moggingcms-core-design.md` (sections 6.4, 6.5, 7.1, 8.1 to 8.7, 9.3, 12.3). Spike evidence: `docs/superpowers/spikes/2026-11-11-rich-text-sentinel-results.md`.

**Plan series:** Plan 1 (core) and plan 2 (markdown) are merged; this plan is written against main `41dd226`. Plan 4 (`@mogging/cli`) is written after this plan merges.

**Owner decisions this plan executes (2026-11-12, agy-first `.clavity/seams/plan3-forks-first.md`, ALIGNED, owner approved all):**
- F1: AI configuration is built by `defineAiConfig` exported from `@mogging/ai`; `mogging.config.ts` exports both `config` (core) and `ai`. Core's `MoggingConfig` is untouched.
- F2: OpenRouter is built in. A `custom` provider kind accepts any AI SDK `LanguageModel` keyed by model id; every model id named anywhere must have a price-table entry (`content_provenance.model_id` is `not null`, `packages/core/migrations/0001_engine.sql:89`). The direct Anthropic, OpenAI, Google and Ollama packages are not bundled in v0.1; an adopter constructs them and passes them as `custom` models.
- F3: `@mogging/ai` owns the SQL on `ai_jobs`, `ai_budgets`, `glossary` and the discarded-cost provenance row. One lock order everywhere: `ai_budgets` rows (scope `global` first, then `collection:<name>`), then the `ai_jobs` row, then `documents` (taken by `recordAiDraft`). The reaper runs in its own committed transaction before each claim. A `{ cancelled }` result from `recordAiDraft` marks the job `CANCELLED`. If the completion transaction fails after a provider call, a separate cost-only transaction records the spend.
- F4: only localized fields whose type contains a `text` or `richText` leaf are sent to the model. Other stale or missing localized fields are reported as `not translatable` and never copied.
- F5: `content_provenance` gains `superseded_version int null` in migration 0001 (still unreleased), filled by `recordAiDraft` when it supersedes a `DRAFT_AI` or `APPROVED` draft head.
- F6: the monthly cap is enforced inside the claim transaction under the budget row lock; a refused job stays `QUEUED` with `error_message = 'budget_exhausted: ...'` and `run_after` pushed forward. The per-run budget is an in-memory tally that stops the run and marks nothing.

## Global Constraints

- Node `>=22`, ESM, TypeScript strict (`tsconfig.base.json`), `engines.node: ">=22"`, `"license": "SEE LICENSE IN LICENSE.md"`, `private: true`, version `0.0.0`.
- Content writes go only through `@mogging/core` public exports (`packages/core/src/index.ts`). This package writes SQL only on `ai_jobs`, `ai_budgets`, `glossary` and the discarded-cost rows of `content_provenance` (`version` and `field_path` null, `discarded` true).
- Prompts and model ids never enter content tables (spec D2). `model_id` and `prompt_version` go to `content_provenance` only.
- Content is passed to the model as data inside a delimited user message, never in the system prompt (spec 8.3). The system prompt holds only the rules.
- Sentinel format `⟦MOGGING:n⟧`; drafts are parsed with text directives disabled (plan 2 already does this inside `restoreDraft`).
- `LINK_TARGETS` is a rejection reason (spike finding 3; `RejectionCode` in `packages/markdown/src/sentinel.ts:7-9`).
- Temperature `0.1` by default. `maxRetries: 0` on the SDK call: retries are the job's `attempts`, so every provider call is accounted.
- Every provider call produces exactly one provenance row per field it covered, or one discarded row (spec 7.1). A call that happened is spend whatever became of its result (spec 8.5).
- `enqueueStale`, `runWorker` and `compile` call `assertLicensed` first (spec 12.3 guards `compile`). Reads (`listJobs`, `listProvenance`, `listGlossary`, `getBudgets`) never do.
- The API key is read from the environment at provider resolution and is never logged, stored or included in an error message.
- Every write takes `ctx.actor` (spec 8.7). The worker's `locked_by` is `<actor>@<hostname>#<pid>` so a lease names a process.
- Tests that need Postgres use a package-local `packages/ai/test/db.ts` identical to `packages/core/test/db.ts`, and need `DATABASE_URL`. No test calls a real provider unless `MOGGING_LIVE=1` and `OPENROUTER_API_KEY` are both set.
- Commit after every green task with a conventional message ending in the session's attribution trailer.

## Review Focus

1. **A worker that loses its lease after the provider returned** (reaper requeued it, or a second worker re-ran it) must write nothing but a discarded-cost row and the budget debit. Otherwise a stale draft overwrites a newer one. Pinned in Task 8 (`a lost lease writes only a discarded row and debits the budget`).
2. **The source head moves between enqueue and completion.** The job must end `CANCELLED`, never `COMPLETED`, and must still debit spend. Pinned in Task 9 (`source moved: job is CANCELLED, cost is debited`).
3. **A job exactly at the monthly cap.** `spent + inflight + estimate == cap` must claim; one micro more must refuse and leave the job `QUEUED` with the reason, not loop forever. Pinned in Task 8 (`claim at the cap boundary`).
4. **A localized `price` number that is stale** (fixture `posts.price` in `packages/core/test/fixtures.ts:14`) must never be sent to the model nor copied from the source. Pinned in Task 7 (`non-text fields are reported, not enqueued`).
5. **A draft that changes a non-text leaf inside a translatable list or object** (the model returns a different count of list items, or a different number inside an object) must be rejected, not stored. Pinned in Task 5 (`a changed non-text leaf is a rejection`).

// and never throws); in the worker it is the prepared wire value.

export function planRequests(args: {

// field is not refused by a large window reservation); the request FITS when T + fixed + reserve(T) <= price.contextTokens.

// with fieldTokens > ai.perFieldTokenLimit gets its own request; another field is appended to the current request while
// the result still fits, else a new request starts. inputTokens = T + fixed; maxOutputTokens = reserve(T) (>= 512).
export function apportion(total: number, shares: number[]): number[];
// Splits an integer total by proportional shares with floor rounding, the remainder on the first element, so the parts
// sum to the total; an all-zero `shares` splits evenly (same remainder rule).
