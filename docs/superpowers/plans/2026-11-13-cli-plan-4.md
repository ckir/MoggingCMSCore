# CLI (`@mogging/cli`) Implementation Plan (Plan 4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `mogging` binary (spec 9.2): a thin command layer over the core, markdown and ai SDKs, plus the four small core additions it needs, plus a `tsc` build so the packages run outside vitest.

**Architecture:** `packages/cli` exports `run(argv, deps): Promise<number>`. Each command is a module returning `{ data, lines, exitCode? }`; `run` owns parsing, project loading, the licence line, printing (`--json` or text) and the exit code, so every command is testable in-process against a test schema with injected IO. Four core functions (`listDraftHeads`, `getDraftReview`, `rejectDraft`, `listReleases`) are added first because the spec says every CLI command is an SDK function (9.3). The build task adds `publishConfig` overrides so development keeps resolving `src` while the packed tarballs point at `dist`.

**Tech Stack:** TypeScript 5, Node >= 22, `node:util` `parseArgs` (no CLI framework), `jiti@2.7.0` (loads only the user's `mogging.config.ts`), `postgres` ^4, vitest ^5, pnpm 12.

**Spec:** `docs/superpowers/specs/2026-11-11-moggingcms-core-design.md` (sections 6.3, 8.5-8.7, 9.2-9.4, 12.3-12.4). Roadmap: `docs/superpowers/specs/2026-11-11-moggingcms-roadmap-design.md`. Forks decided with the owner and agy: seams `.clavity/seams/plan4-forks-first.md`, `.clavity/seams/plan4-build-query-first.md` (replies under `.clavity/scratch/plan4-forks/` and `plan4-build-query/`). ## Owner decisions (2026-11-13)

- **D-reject:** a distinct core `rejectDraft` is added (whole-draft reject). Rejecting every field through `approve` would insert an `APPROVED` head, empty `{}` when nothing is published, and `publishCore.ts:45` publishes `APPROVED` heads.
- **D-stale:** `review approve|reject` must act only on the draft version the reviewer saw. Core `approve` and `rejectDraft` gain an optional `expectedVersion` (the idiom of `saveDraft.expectedVersion`, `packages/core/src/documents/saveDraft.ts:15,65`; spec 7.2: "a write that expected a different current version fails with a conflict"); the CLI's `review approve` and `review reject` REQUIRE `--version <n>` (the version `review list|show` print) and interactive review passes the version it showed. `approveClean` is unchanged (its contract is "approve any warning-free head found under the lock"). Agy and the plan author recommended this; the owner chose it. The requirement is a race guard against acting on a replaced draft: a script can pass the number from `review list --json`, so it proves which version was acted on, not that a person read it (attribution, like the actor).
- **D-warn:** spec 8.4 ("refuses to approve a draft with warnings unless the reviewer acknowledges each one by name; the acknowledgement is recorded in provenance") is enforced in CORE: `approve` throws `ValidationError` unless `acknowledgedWarnings` equals, as a set, the distinct warning texts the draft carries (the draft row's `field_warnings`, Task 1 and D-fwarn, filled from the AI call's `content_provenance.warnings`, `0001_engine.sql:99`; a warning's only identity is its text, and call-level warnings repeat on every field row, `packages/ai/src/translate.ts:211`, so one text acknowledged once covers them all). The check runs under the document lock after the `expectedVersion` check, so a stale acknowledgement for a replaced draft is a `ConflictError`, not a silent approval. `approveClean` skips a draft whose `field_warnings` holds any text (today it reads only the draft version's rows, `approve.ts:90`, so a carried-over warned field was bulk-approved). The CLI passes a repeatable `--ack-warning <text>` through and the interactive review asks per warning. Agy (agy-first, ALIGNED) and the plan author recommended this; the owner chose it (2026-11-13).
- **D-fwarn:** the warnings a draft still carries are stored ON the `document_localized` row as `field_warnings jsonb not null default '{}'` (field path -> distinct warning texts), merged by `recordAiDraft` the way it merges `source_hashes` (`recordAiDraft.ts:91-96`), and written `{}` by `approve` (an acknowledged warning is never demanded again for that text; only a field the AI re-drafts brings new warnings). The gate, `approveClean`, `listDraftHeads` and `getDraftReview` read that one row under the lock. This replaces a provenance walk that panel round 4 broke: `trackFields` writes a warning-free `human:track` row on the draft-head version (`state.ts:151-155`), a draft based on a rejected row has `superseded_version` null (`recordAiDraft.ts:89`), and `provenance: []` is legal, so lineage rebuilt from `content_provenance` failed open. `content_provenance` stays the audit log of AI calls, unchanged. Agy (agy-first, ALIGNED) and the plan author recommended this and "acknowledge once"; the owner chose both (2026-11-13).
- **D-build:** compile packages to `dist/` with plain `tsc` inside this plan (last code task). No npm publish, no version change (the owner's). `jiti` loads only the user's config; the CLI and SDK never run through a runtime transpiler.
- **D-query:** a minimal read-only `mogging query <collection>[/<slug>] [--locale] [--json] [--raw]`; no SQL, no writes.
- **Joint calls:** `parseArgs` plus a hand router; local review web page DEFERRED to v0.2 (spec 8.6 says "can"; section 11 does not need it); interactive review is a thin layer over flag-driven subcommands; `$EDITOR` in interactive mode, `--edit-file` JSON in CI; `release add --all-approved`; `init` never overwrites an existing config.
- **Plan-author calls, not yet owner-ratified (flagged in the handoff):** `rejectDraft` is NOT licence-guarded (it only removes a draft head; spec 12.3 lists the guarded set exactly, so 12.3 gains it in the not-guarded list); `publish` with no `--locale` publishes every `DRAFT_HUMAN`/`APPROVED` head of the document and refuses `DRAFT_AI` ones; edit files accept only `text` and `richText` top-level localized fields.

## Global Constraints

- Command list (spec 9.2): `init`, `migrate`, `import`, `export`, `status`, `track`, `compile`, `worker`, `review`, `publish`, `unpublish`, `release create|add|publish`, `jobs`, `provenance`, `query`.
- `compile` requires `--locales` and `--budget` (8.5: "the CLI refuses to compile without them"); the monthly cap is already required by `defineAiConfig`.
- No unconditional "approve all" (8.6). The only bulk path is `review --approve-clean [--collection] [--locale]` over `approveClean` (`packages/core/src/documents/approve.ts:164`).
- `publish` has no unscoped form (9.2): one document, or `--release <name> [--allow-stale]`.
- Every write takes an actor (8.7). The CLI actor is `--actor`, else `MOGGING_ACTOR`, else the OS user name, else `cli`; never empty. Attribution, not authentication.
- Every command that opens the project prints the licence line to STDERR (12.3, 12.4): evaluation days left (warning form from 7 days left), the expired notice, or for a `noncommercial` key exactly `MoggingCMS noncommercial licence: commercial use is not permitted` followed by the licensee. With `--json` the same facts are also in the `licence` member of the JSON document, so redirecting stderr cannot hide them.
- Guarded operations are exactly `saveDraft`, `recordAiDraft`, `approve` (and `approveClean`), `publish`, `publishRelease`, `compile` (12.3). Not guarded: all reads, `unpublish`, `createRelease`, `addToRelease`, `trackFields`, and now `rejectDraft`.
- Exit codes (a CLI contract, pinned by tests and the README): `0` ok, `1` error, `2` usage, `3` licence refusal (`LicenceError`), `4` partial failure. **One rule decides 1 versus 4:** a command that attempts several items (import files, publish heads, release items, compile jobs, `jobs --retry` ids) exits `4` when at least one item succeeded or was already done and at least one failed or was refused; when every attempted item failed or was refused it exits `1`; an item that was already in the wanted state ("unchanged", "already in release") counts as done, not as a failure. A command that attempts one thing exits `0` or `1`. `--approve-clean` skips are not failures (they are the check working): exit `0`. As a formula, each multi-item command names two counters, `failed` and `done`: `failed = 0` -> `0`; `done = 0` and `failed > 0` -> `1`; both `> 0` -> `4`.
- `--json`: a command's stdout is exactly one JSON document and nothing else (`--version`, `--help` and the no-verb usage text are not command results and stay plain text with or without `--json`). `data` is the return value of the SDK call the command wraps, unchanged: `review list` -> `{ items, next: null }` with the items of every page `listDraftHeads` returned, `review show` -> `DraftReview`, `review approve|reject` -> `{ version }`, `--approve-clean` -> `ApproveCleanResult`, `release create` -> `createRelease`'s result, `release list` -> `listReleases`'s array, `release publish` -> `null` (`publishRelease` returns `void`, `releases.ts:82`), `compile` -> the ai `compile` result, `worker` -> the final `WorkerReport`, `track` -> `null` (`trackFields` returns `void`, `state.ts:107`), `provenance` -> the row array; `publish`, `unpublish` and `release add` return `{ items: Array<{ target: string; locale: string; outcome: string; version?: number; message?: string }> }` whose `outcome` is the word their human lines print; `init`, `migrate`, `import`, `export`, `status`, `jobs` and `query` keep the shape their task names (`jobs --retry|--cancel` -> the `retryJobs`/`cancelJobs` result; `jobs` -> `{ jobs, budgets }`). `publish --release` on a `StaleReleaseError` returns exit 1 with `data: { stale: err.items }` and `error` (it does not throw to `run`), so the stale items reach `--json`. Exit `0` and `4`: `{ "ok": true, "partial": false|true, "data": ..., "licence": ... }` (`partial: true` exactly when the exit code is `4`). A command that RETURNS exit `1` (every item failed, nothing threw): `{ "ok": false, "partial": false, "data": ..., "error": { "code": string, "message": string }, "licence": ... }` where `error` is the result's own `error` member (Task 2 `CommandResult`). A throw: `{ "ok": false, "error": { "code": string, "message": string }, "licence": ... }` (no `data`) where `code` is the error's own string `code` when it has one, else its `name`. So `ok` is true exactly for exit codes `0` and `4`. `licence` is `{ "state": "licensed"|"evaluation"|"expired", "daysLeft": number|null, "warn": boolean, "plan": string|null, "licensee": string|null, "keyError": string|null }` (`null` when the command did not open a project). Progress and the licence line go to stderr. Human mode prints errors to stderr as `error: <message>`. `--json` with interactive review is a `UsageError` (no JSON form).
- Secrets: any printed text has database URL passwords replaced by `***` (`run` applies `maskSecrets` to every stdout and stderr write, human lines and serialized JSON alike, not only to error messages); the provider key (`OPENROUTER_API_KEY`) is never read by the CLI (the ai package reads it).
- Errors are mapped by `err.name`/`err.code`, never `instanceof`, because the user's config may load a second copy of `@mogging/core`.
- Dependencies are pinned exactly (`jiti` 2.7.0) like `packages/ai/package.json`; `engines.node >=22`; package `license` `SEE LICENSE IN LICENSE.md`.
- Test commands: `pnpm --filter <pkg> test <file-filter>` (NOT `test -- <filter>`, see `docs/dev-setup.md`); full gate `DATABASE_URL=postgres://mogging:mogging@127.0.0.1:54329/mogging_test pnpm test && pnpm typecheck`.

## Review Focus

Failure modes the spec implies but no command's happy path exercises, most likely first; the owning task pins each.

1. `publish`/`release add` aimed at a `DRAFT_AI` head must refuse with a message naming `mogging review`, never publish AI text (Task 6, Task 7).
2. `compile` with no `--budget` or no `--locales` exits 2 before any database connection or spend (Task 5).
3. A database URL with a password inside an error message must print `***` (Task 2).
4. `init` on a directory that already has `mogging.config.ts` leaves it byte-identical (Task 3).
5. With `--json`, stdout stays one parseable document even when the licence warning fires (Task 2); `worker` stops cleanly on an aborted signal (Task 5).
6. A refused database connection prints a non-empty message (Task 2): the driver raises an `AggregateError` with an empty `message` for `localhost` (measured with the locked `postgres`).
7. End of input at the interactive prompt ends the review cleanly instead of hanging (Task 8): `question()` is not used, because it never settles for a line that arrived before it was called and throws once the input has ended (measured).
8. Ctrl-C during `compile`, `import` or `export` still kills the process (Task 2): a command that does not consume the abort signal must not get a SIGINT handler.
9. `--edit-file` changes only the fields the reviewer actually changed; an unedited carried-over field keeps its recorded source hash and is not marked edited (Task 7).
10. A draft with warnings is never approved without every distinct warning text acknowledged, through the SDK, the flag-driven CLI or the interactive review (Task 1, Task 7, Task 8; D-warn).
